# Стратегия и регламент тестирования (`TESTING`)

> **Связанные документы:** [Отчёт проверки 0.15.0 (`../TEST_REPORT_RU.md`)](../TEST_REPORT_RU.md) · [Чек-лист сборки 0.15.0 (`../BUILD_CHECKLIST.md`)](../BUILD_CHECKLIST.md) · [Качество релиза (`RELEASE_QUALITY.md`)](RELEASE_QUALITY.md) · [Прокачка (`PROGRESSION.md`)](PROGRESSION.md) · [ИИ монстров (`MONSTER_AI.md`)](MONSTER_AI.md) · [Бюджеты нагрузки (`PERFORMANCE_BUDGETS.md`)](PERFORMANCE_BUDGETS.md) · [Сохранения (`SAVE_DATA.md`)](SAVE_DATA.md) · [Известные проблемы (`KNOWN_ISSUES.md`)](KNOWN_ISSUES.md)

Настоящий документ определяет классификацию тестов в проекте **Living Civilization**, требования к покрытию подсистем и фактические результаты проверок текущего состояния репозитория.

---

## 1. Строгое разграничение уровней проверки

В проекте категорически запрещено выдавать документальную или статическую проверку исходного текста за автоматическое тестирование работающего мода. Все проверки делятся на 6 уровней:

| Уровень | Что проверяет | Требует ли Minecraft classpath / запуск игры | Что подтверждает |
|---|---|---|---|
| **0. Статическая проверка (`Static Check`)** | Синтаксис Java (`JavaSyntaxCheck.java`), баланс скобок, валидность JSON переводов, `sh -n`, наличие маркеров в тексте (`validate_project.py`, `test_*.py`). | Нет | Только отсутствие грубых синтаксических опечаток и наличие ожидаемых констант в исходниках. **Не подтверждает компиляцию и работоспособность.** |
| **1. Модульные тесты (`Unit Tests`)** | Чистая логика независимого ядра (`domain.*`): материальные ведомости, расчёт опыта и уровней, приоритеты, выбор целей, чистые функции миграции схем. | Нет (чистая JVM / JUnit) | Корректность алгоритмов и бизнес-правил, а также переносимость доменного ядра без зависимостей от Minecraft API. |
| **2. Интеграционные тесты (`Integration Tests`)** | Взаимодействие между модулями, портами и адаптерами (`domain ↔ ports ↔ platform`), сериализация/десериализация `CompoundTag` и `SavedData`. | Частично (тестовое окружение с библиотеками Minecraft/NeoForge) | Согласованность контрактов данных, отсутствие потерь при сохранении и корректность трансляции DTO. |
| **3. Игровые функциональные тесты (`Game / Functional Tests`)** | Полные пользовательские и симуляционные сценарии в мире (`./gradlew runClient`, `./gradlew runServer`, `gameTestServer`). | Да (полный запуск клиента и сервера) | Реальное поведение жителей и мобов, навигацию `WALK_TARGET`, установку блоков, GUI старосты и сетевые пакеты. |
| **4. Регрессионные тесты (`Regression Tests`)** | Автоматизированные или сценарные проверки ранее обнаруженных и исправленных ошибок. | Зависит от слоя ошибки (`Unit` / `Integration` / `GameTest`) | То, что исправленный баг не появился повторно при новых изменениях. |
| **5. Нагрузочные тесты (`Performance Tests`)** | Замер MSPT/TPS, памяти и GC на профилях нагрузки `L1–L7` (см. [`PERFORMANCE_BUDGETS.md`](PERFORMANCE_BUDGETS.md)). | Да (запущенный мир с профилировщиком) | Соблюдение бюджетов производительности и отсутствие утечек ресурсов на длинной дистанции. |

## 2. Фактические результаты проверок в текущем состоянии репозитория (`8635934`)

При аудите репозитория на ветке `arena/fbf16766-minecraft-mod` выполнены доступные проверки со следующими реальными результатами:

| Команда | Статус | Фактический результат и причина |
|---|---|---|
| `sh -n gradlew BUILD_LOCAL.sh` | `PASS` | Shell-синтаксис обоих скриптов корректен (код возврата `0`). |
| `python3 -m json.tool en_us.json > /dev/null && python3 -m json.tool ru_ru.json > /dev/null` | `PASS` | Оба файла локализации являются валидным JSON. |
| `python3 validate_project.py` | `FAIL` | `FileNotFoundError: [Errno 2] No such file or directory: '/home/user/gradle.properties'`. Скрипт ожидает расположения в подкаталоге `tools/validate_project.py`, тогда как при коммите `8635934` все файлы были загружены плоско в корень репозитория (см. [`KNOWN_ISSUES.md`](KNOWN_ISSUES.md)). |
| `java JavaSyntaxCheck.java .` | `NOT RUN` / `FAIL` | `/bin/bash: line 1: java: command not found` — в контейнерной среде аудита не установлен JDK 21. |
| `./gradlew build` | `FAIL` | `/bin/bash: line 1: ./gradlew: Permission denied` — при веб-загрузке файлов потерян бит исполнения (`-rw-r--r--`). |
| `sh gradlew build` | `FAIL` | `curl: (35) OpenSSL SSL_connect: SSL_ERROR_SYSCALL in connection to services.gradle.org:443` — в изолированной среде нет сетевого доступа к `services.gradle.org` для скачивания Gradle 9.2.1 и Maven-репозиториев NeoForge/Minecraft. |
| `./gradlew runClient` / `./gradlew runServer` | `NOT RUN` | Заблокировано отсутствием полной сборки, JDK 21 и графического/игрового окружения. |

## 3. Обязательный каталог проверок по подсистемам

### 3.1. Компиляция и проверка переносимости доменной логики (`LANGUAGE_PORTABILITY`)
- [ ] Полная компиляция проекта `./gradlew build` без ошибок и предупреждений о неразрешённых символах.
- [ ] Проверка отсутствия импортов `net.minecraft.*`, `com.mojang.*`, `net.neoforged.*` в пакете `domain` ([`LANGUAGE_PORTABILITY.md`](LANGUAGE_PORTABILITY.md)).
- [ ] Автономный запуск unit-тестов доменного ядра отдельно от игрового окружения.

### 3.2. Экономика, строительство и базовые роли (`0.15.0` → `TESTED`)
Детальный пошаговый список из 18 ресурсных сценариев приведён в [`../BUILD_CHECKLIST.md`](../BUILD_CHECKLIST.md). Ключевые проверки:
- [ ] Отсутствие генерации саженцев, инструментов, досок, булыжника, слитков и еды из воздуха.
- [ ] Атомарность складских транзакций при нехватке входных ресурсов и при полностью заполненных сундуках.
- [ ] Пошаговое строительство хижины (`VillageBuilder`: 96 досок одного типа + подходящая дверь + красная кровать) и фермы 5×5 (`VillageFarmBuilder`: 24 семени + ведро воды с возвратом пустого ведра + компостер + мотыга).
- [ ] Многорейсовый сбор ингредиентов ремесленником (`VillageCraftingJobs`) из разных сундуков.
- [ ] Доставка еды курьером (`VillagePopulation`) самому голодному взрослому при наличии свободной кровати с зазором по высоте (`hasBabyClearance`).
- [ ] Серверная валидация команд панели старосты (`VillageElder`: UUID, маркер старосты, дистанция, включённость настроек).

### 3.3. Тесты минимальной системы прокачки (`PROGRESSION` — статус `PLANNED`)
Полные требования описаны в [`PROGRESSION.md`](PROGRESSION.md):
- [ ] **Unit / Functional:** опыт начисляется строго за завершённое полезное действие (срубленное дерево, добытая руда, завершённый крафт, уложенный этап стройки).
- [ ] **Unit / Functional:** опыт **не начисляется** за бесконечные неудачные попытки навигации, ожидание саженца/ресурса или отменённые заказы.
- [ ] **Unit:** при достижении порога опыта уровень профессии повышается (в пределах шкалы 1–5).
- [ ] **Unit / Integration:** смена рабочей роли (`miner → builder → miner`) сохраняет ранее набранный опыт каждой профессии.
- [ ] **Integration / Game:** сохранение, выход и повторная загрузка мира полностью сохраняют опыт и уровни жителей.
- [ ] **Integration:** миграция старого сохранения (`0.15.0`) без полей прокачки проходит без ошибок.
- [ ] **Functional:** бонусы уровня не создают бесплатных предметов и не уменьшают материальную ведомость рецептов/чертежей.

### 3.4. Тесты поведения и восприятия мобов (`MONSTER_AI` — статус `PLANNED`)
Полные требования описаны в [`MONSTER_AI.md`](MONSTER_AI.md). Для каждого типа моба (зомби, скелеты, криперы, пауки, ведьмы, разбойники):
- [ ] Обнаружение цели только при допустимых условиях видимости/дистанции/сигнала.
- [ ] Отсутствие всеведения (моб не идёт к жителю или складу за сплошной глухой стеной без предварительного контакта).
- [ ] Потеря цели и прекращение преследования по тайм-ауту.
- [ ] Ограничение числа повторных попыток пути при заблокированном входе без спама `PathNavigation`.
- [ ] Безопасная отмена задачи при выгрузке целевого чанка (без принудительной подгрузки чанков).
- [ ] Соблюдение `mobGriefing = false` (особенно для криперов и зомби).
- [ ] Корректная работа как в одиночном мире, так и на выделенном сервере (`dedicated server`).

### 3.5. Граничные, аварийные и миграционные сценарии (`SAVE_DATA` & `AI_BEHAVIOR`)
- [ ] **Сохранение, выход и повторная загрузка мира:** сохранение прогресса постройки дома/фермы на промежуточном шаге (включая установку двух половин двери и кровати) без потери материалов.
- [ ] **Миграция сохранений:** чтение данных предыдущей поддерживаемой версии схемы и последовательный переход `v0 → v1`.
- [ ] **Повреждённые, неполные и неизвестные данные:** подача некорректных NBT-тегов не роняет сервер, не стирает неизвестные поля и не перезаписывает исходные данные пустым состоянием.
- [ ] **Работа при нехватке ресурсов:** корректный переход задач в `WAITING_FOR_RESOURCES` без зависания остальной деревни.
- [ ] **Гибель или удаление жителя во время задачи:** освобождение зарезервированного заказа в поселении и сохранность выпавших реальных предметов.
- [ ] **Выгрузка чанка во время задачи:** безопасная пауза и возобновление работы после возвращения чанка в активную зону.
- [ ] **Застрявшая навигация и повторная неудача:** срабатывание тайм-аута (`TASK_TIMEOUT_TICKS`) и карантина недоступной цели без бесконечного цикла.
- [ ] **Длительная симуляция и профилирование:** выполнение нагрузочных профилей `L1–L7` из [`PERFORMANCE_BUDGETS.md`](PERFORMANCE_BUDGETS.md).
